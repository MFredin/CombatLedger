CombatLedger
A post-combat analysis engine for World of Warcraft Midnight (12.0+) — bringing full-fidelity log data back into the game client via a lightweight companion architecture.
Version 0.1 Draft
Target WoW Midnight 12.0.1+
Distribution CurseForge · GitHub
License MIT (Addon) · Proprietary (Companion)
01 Architecture Overview
Core Design Principle
The in-game addon is a visualization layer only. All parsing, enrichment, and computation happens in the companion app outside the Lua sandbox. This keeps the addon thin, fast, and API-compliant — the companion does the heavy lifting. Communication happens via SavedVariables written to the WTF directory, with a /reload or automatic trigger completing the sync loop.
Companion App
TypeScript / Tauri
Lightweight background process. Watches WoWCombatLog.txt using a native file watcher. Parses every CLEU event in real time, segments by encounter/pull, enriches events with context (overkill flags, DR chains, spell metadata), then serializes structured data into the addon's SavedVariables file. Minimal CPU/memory footprint — targeting <1% CPU idle.
In-Game Addon
Lua · WoW API
Reads SavedVariables on load and renders the UI. Uses Blizzard's permitted frame APIs and textures. No CLEU parsing, no combat logic — purely presentational. Ships with a full configuration panel, preset system, and per-character settings. Signals the companion app for a re-export via a configurable chat command or macro.
Data Bridge
SavedVariables · WTF/
Companion writes a CombatLedger.lua SavedVariables file to the character's WTF directory. Structured as nested Lua tables: session → pull → events. Addon reads this on each UI load. Total data size for a full M+ key typically 80–200 KB — well within WoW's SavedVariables limits.
Spell Metadata DB
Bundled JSON
Static spell database bundled with the companion app — sourced from Wowhead/WoWDB exports and supplemented manually. Maps spell IDs to: name, school, interruptible flag, CC type, DR category, and priority tier. Updated each patch. Enables the companion to enrich raw log event IDs into meaningful, labeled data before it reaches the addon.
02 Features & Complexity
Feature Description Layer Complexity
Companion Log Watcher File watcher tailing WoWCombatLog.txt in real time, writing to SavedVariables after each encounter Companion Low
CLEU Event Parser Full parsing of SPELL_DAMAGE, UNIT_DIED, SPELL_INTERRUPT, SPELL_AURA_APPLIED, COMBATANT_INFO etc. into typed structs Companion Medium
Death Recap Engine Reconstructs the causal event chain leading to each UNIT_DIED: last N damage events, incoming heals, overkill value, active/available defensives at time of death Companion Medium
Interrupt Report Per-cast interrupt tracking: which player interrupted what, at what % of cast completion, or if the cast went through and why (no one in range, CDs unavailable) Companion Medium
CC Coverage Visualizer Timeline-style CC chain per target: which spell, which player, duration, DR reduction (requires DR category database), gaps between CC windows Companion + Addon High
Player Performance Panel Per-player: DPS/HPS from Blizzard meter data, cast uptime %, interrupts contributed, CC contributed, deaths, defensive usage Addon + Blizzard API Low
In-Game UI Framework Tabbed panel system, player/pull filter chips, preset system with save/load, per-character layout persistence Addon (Lua) Medium
Spell Metadata Database Static JSON bundled in companion: spell ID → name, interruptible, CC type, DR category, priority. Requires manual curation per patch Companion (bundled) Medium
Cross-Run Trend Tracking Session-over-session comparison: interrupt rate, death count, uptime trends. Persisted per character-dungeon pair Companion + Addon High
Companion Auto-Installer CurseForge-distributed package that bundles the companion app alongside the addon. Auto-detects WoW install path, registers as startup item (opt-in) Packaging / DevOps High
Export / Share CSV export of any panel view. Optional: JSON export for WarcraftLogs-compatible upload format (post-run, not real-time) Companion Low
Avoidability Annotation Flags deaths and hits as "avoidable" vs "unavoidable" based on spell type metadata (swirlies, targeted AoEs, etc.) and player position/movement data Companion Very High
Defensive Usage Audit Cross-references SPELL_CAST_SUCCESS for known defensive cooldowns with damage spike windows — flags available defensives that weren't used near death events Companion High
03 Phase Roadmap
Phase 1 — Foundation & Core Loop
Weeks 1–8 · ~2 months
  • ARCH
    Tauri companion app scaffold
    Rust backend + TypeScript frontend. Auto-detects WoW install path on Windows and macOS. File watcher on WoWCombatLog.txt. Writes to WTF/SavedVariables on ENCOUNTER_END detection.
  • CORE
    CLEU parser — damage & death events
    Parses SPELL_DAMAGE, SWING_DAMAGE, RANGE_DAMAGE, UNIT_DIED, UNIT_DESTROYED, COMBATANT_INFO. Segments by ENCOUNTER_START / ENCOUNTER_END. Outputs typed structs per pull.
  • CORE
    Death recap engine (v1)
    Reconstructs last 10 seconds of damage/heal events before UNIT_DIED for each player. Calculates overkill. Identifies fatal spell. Bundles into SavedVariables per death.
  • CORE
    Interrupt report (v1)
    Parses SPELL_INTERRUPT events. Matches to SPELL_CAST_START/SUCCESS on enemies to determine cast completion % at interrupt. Flags uninterrupted casts that were interruptible.
  • UX
    In-game addon — core UI shell
    Tabbed frame with Deaths and Interrupts tabs. Player filter chips. Opens via slash command /cl or minimap button. Reads SavedVariables and renders static data. No real-time parsing in addon.
  • ARCH
    Spell metadata database v1
    Initial JSON covering Darkflame Cleft, Priory of the Sacred Flame, and the Rookery — the Midnight launch M+ pool. Interruptible flag and CC type per relevant enemy spell.
Total Complexity
Medium
Primary Language
TypeScript + Lua
Primary Risk
SavedVariables size limits under heavy logging (mitigation: rolling window, compression)
WoW install path detection edge cases on non-standard installs
Milestone
Alpha release on CurseForge — Deaths + Interrupts tabs functional
Phase 2 — CC, Performance & Presets
Weeks 9–18 · ~2.5 months
  • CORE
    CC coverage engine with DR tracking
    SPELL_AURA_APPLIED / REMOVED parsing per target GUID. DR category database applied to calculate effective duration vs theoretical. Timeline data structure for visualizer. Breaks and early removals flagged.
  • UX
    CC Coverage tab — timeline visualizer
    Horizontal CC chain bars per target. Color by player. DR indicated by opacity. Gap windows shown. Interactive: hover for spell/player tooltip, click to jump to that moment in the death timeline if correlated.
  • UX
    Performance tab
    DPS/HPS sourced from Blizzard's native meter API (via addon). Cast uptime calculated from log. Interrupt + CC contributions per player. Defensive spell usage summary. Deaths and their impact on uptime clearly visualized.
  • UX
    Preset system
    Save current filter state (players, pull, tab, view options) as a named preset. Ship with built-in presets: "Deaths Only", "Tank Focus", "Healer Audit", "M+ Push Review". Presets stored per-character in SavedVariables.
  • CORE
    Defensive usage audit (v1)
    Cross-reference known defensive spell IDs (Bubble, Feign, Cloak, Blur, etc.) with SPELL_CAST_SUCCESS. Flag cases where a player died and had a defensive available but unused within a ±5s window.
  • DATA
    Full M+ dungeon pool metadata
    Expand spell database to cover all Midnight Season 1 dungeons. Community contribution pipeline via GitHub PRs for spell metadata — reduces ongoing maintenance burden.
  • UX
    CSV / JSON export
    Export any panel view as CSV from the companion app. JSON export in a WarcraftLogs-compatible schema for users who want to cross-reference with external tools without re-uploading.
Total Complexity
High
Primary Language
TypeScript + Lua
Primary Risk
DR category database correctness — errors here produce misleading CC visualizations. Needs testing with real log data.
Blizzard meter API surface may change in 12.0.1 patches during development window
Milestone
Beta release — all 5 tabs functional. Community feedback loop open.
Phase 3 — Trend Intelligence & Distribution
Weeks 19–28 · ~2.5 months
  • CORE
    Cross-run trend engine
    Persistent session history in companion app (SQLite). Tracks interrupt rate, death count, CC coverage %, uptime %, and cast efficiency per player over N runs of the same dungeon. Surfaces trends: "Korryn's interrupt rate has dropped 20% over last 3 keys."
  • UX
    Trend tab in-game
    Spark-line style per-player improvement/regression indicators per metric. "Last 5 runs" view. Click to expand full history. Useful for consistent groups tracking week-over-week improvement during a season.
  • CORE
    Avoidability annotation (v1)
    Tag damage events as avoidable vs unavoidable using spell metadata (ground AoEs, frontal cones, targeted swirlies). Annotates death recaps and damage-taken summaries with avoidability flag. High maintenance cost — requires manual review per new patch.
  • ARCH
    Companion one-click installer
    CurseForge package that bundles addon + companion installer. Platform-native installers (NSIS on Windows, .dmg on macOS). Optional: auto-launch on WoW startup. Open-source companion code on GitHub for trust/transparency.
  • DATA
    Raid encounter support
    Extend spell metadata and analysis logic to cover raid encounters. Death recaps and interrupt reports particularly high-value in raid context. Encounter-specific notes (e.g., flag deaths to specific boss mechanics).
  • UX
    Shareable run summary link
    Optional: Companion app generates a static HTML summary of the run, hosted locally or on a lightweight CDN. Share link in Discord. No account required. Privacy-preserving — all processing stays local.
Total Complexity
Very High
New Tech
SQLite (local DB)
Primary Risk
Installer trust/friction — players are skeptical of companion software. Mitigate with open source code, CurseForge distribution, and clear privacy policy.
Cross-run normalization complexity — different group compositions make trend comparisons noisy. Requires thoughtful data model.
Milestone
v1.0 stable release. Full feature set. Community adoption push.
